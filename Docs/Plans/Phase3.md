## C. Tasks

### 1. Animation states (Player/PlayerAnimator.cs + new Player/ProceduralPose.cs)
1.1 `ProceduralPose : MonoBehaviour` on the robot model (added by the prefab builder). In `LateUpdate` (after the
    Animation component) it adds extra local rotations to bones found by name (`Spine1`, `LeftArm`, `RightArm`,
    `LeftUpLeg`, `RightUpLeg`, `Hips`). Public API: `SetPose(PoseKind kind, float weight)` where
    `enum PoseKind { None, Jump, Fall, Hover, Hurt, Dead }`; weight eases toward the target at 10/s.
    - Jump: Spine1 pitch -12°, both arms raised 60° (rotate around local Z, mirrored), legs tucked 25°.
    - Fall: arms spread 80°, legs 10°.
    - Hover: arms down 20°, legs together, small sine bob on Hips (±0.03 m at 6 Hz).
    - Hurt: Spine1 pitch +20° for 0.25 s (auto-returns to None).
    - Dead: Hips roll 80° and drop 0.4 m over 0.4 s.
1.2 `PlayerAnimator`: choose the pose every frame — Dead if `PlayerHealth.IsDead`; Hurt for 0.25 s after
    `GameEvents.OnPlayerHealthChanged` lowers HP; Hover if `IsHovering`; Jump if airborne and `Velocity.y > 0.5`;
    Fall if airborne and `Velocity.y < -1`; else None.
1.3 If clips named `Jump`, `Fall`, `Hit`, `Death` exist on the legacy Animation component (the prefab builder's
    `AttachLegacyClips` already adds every clip found in `Art/Animations`), play them via CrossFade instead and set
    the procedural pose weight to 0 for that state.
1.4 Prefab builder: add `ProceduralPose` to the robot model in the Player prefab; set `PlayerAnimator` reference.

### 2. Flying enemy (World/FlyingDrone.cs)
2.1 `FlyingDrone : MonoBehaviour, IDamageable, IStompable` with the same nested-class state machine style as
    `PatrolEnemy`: `Hover` (bob ±0.3 m, slow yaw), `Patrol` (loop through `Vector3[] waypointOffsets` at hover
    height), `Telegraph` (0.6 s: shake + emissive flash via MaterialPropertyBlock `_EmissionColor` red), `Dive`
    (fly in a straight line to the player position captured at telegraph start, speed 14, max 1.2 s),
    `Recover` (1 s climb back to hover height), `Dead` (drop loot: 3 bolts via `Bolt.Pop`, debris fx, `SfxId.EnemyDie`).
    Detect player within 9 m with line of sight (layers Default|Ground block).
2.2 Contact (trigger + kinematic Rigidbody like PatrolEnemy): hurts the player unless the player is spinning
    (then the drone dies) or comes from above (drone dies, player `Launch(11)`).
2.3 Prefab `Enemy_Drone` in `BuildPrefabs()`: model `Art/Enemies/companion-drone-1d073f.glb` size 1.1 (MaxDimension),
    layer Enemy, SphereCollider trigger, kinematic Rigidbody, loot/fx references like Enemy_Beetle.

### 3. New world mechanics (World/)
3.1 `EnemyWaveTrigger`: trigger volume; on first player enter activates a list of inactive enemy GameObjects
    (`GameObject[] enemies`) and closes optional `GameObject[] gates` (set active). When all enemies are inactive
    (check in Update every 0.25 s, no allocations) it opens gates and raises `UnityEvent onCleared` — but since we
    don't wire UnityEvents in YAML, also expose `GameObject[] revealOnClear` that it SetActive(true)s.
3.2 `Spinner`: rotating hazard bar (rotates around Y at `degreesPerSecond`); any player touching its trigger
    collider gets `TakeHit`. Visual: a scaled `dock-platform-section` plank.
3.3 `CrumblingPlatform`: when the player stands on it (detect via `PlayerMotor.OnHit` is not available per object —
    use a thin trigger on top), shakes for 0.6 s, falls (disable collider, move down 6 m over 0.8 s), respawns after 3 s.
3.4 `Collectibles/BoltRing`: no new class — just an editor helper `SpawnBoltRing(parent, center, radius, count, prefix, ref index)`.
